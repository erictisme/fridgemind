## 2026-01-10: Bug #1 ATTEMPTED but NOT FIXED (PRD id:1)
**Problem:** When user wrote detailed requests like "want to make bittergourd juice with lemon, orange, turmeric, ginger", system ignored request and generated random inventory-based recipes instead.

**First attempt (FAILED):** Updated generateMealSuggestions in src/lib/gemini/vision.ts:
- Added detection for specific recipe requests (keywords: make, want, juice, blend, soup, smoothie, salad, dish, recipe)
- When detected, prompt now makes user's request the PRIMARY goal with **CRITICAL** priority
- Prompt instructs AI to generate the EXACT dish requested, check inventory for matching ingredients, list what's missing

**WHY IT DIDN'T WORK:**
The fix was superficial. The prompt structure is STILL inventory-first:
- Line 560: "You are a creative home chef assistant. Generate exactly N practical meal suggestions based on this inventory."
- This PRIMES the AI to think inventory-first regardless of any "CRITICAL" labels later in the prompt
- The remarks/request gets buried after the inventory list

**REAL FIX NEEDED:**
- When user has a specific request, the ENTIRE prompt must be restructured
- First line should be: "The user wants to make: [request]. Help them make this using their inventory."
- Request-first, inventory-supports - not inventory-first, request-second
- The keyword detection approach is also too brittle

**Status:** Reverted to passes: false in PRD for re-attempt

## 2026-01-10: NEW APPROACH for Recipe Generation (PRD id:1 rewritten)
**Decision:** Instead of trying to detect user intent with fragile keyword matching, add an EXPLICIT mode toggle.

**Two modes:**
1. **"What can I make?"** (inventory mode) - current behavior, unchanged
2. **"I want to make..."** (recipe mode) - new, recipe-first prompt

**Why this is better:**
- No ambiguity - user explicitly chooses their intent
- No brittle keyword detection
- Each mode gets a prompt optimized for its purpose
- Clear mental model for users

**Implementation plan:**
- UI: Add mode toggle buttons at top of Inspire page
- UI: Conditionally show ingredient picker (inventory mode) or recipe input (recipe mode)
- API: Accept `mode` param, pass to generateMealSuggestions
- Prompt: Two completely different prompts - inventory-first vs recipe-first
- Cleanup: Remove the hasSpecificRecipeRequest keyword detection

**See PRD id:1 for step-by-step instructions**

**Solution:** Removed the feature entirely.

**Decisions:**
- Removed vs fixed because: feature was niche (backfill-only), confusing to users, normalization now happens at upload time
- No data migration needed - old unnormalized items still display their raw names, just slightly uglier

## 2026-01-10: Feature #1 Complete - Two-mode recipe suggestions (PRD id:1)
**Problem:** User's recipe requests like "bittergourd juice with lemon, ginger, turmeric" were ignored because the prompt was inventory-first. Keyword detection approach failed - the prompt still primed AI to think inventory-first.

**Solution:** Explicit mode toggle instead of brittle keyword detection.
- Added mode toggle UI: "What can I make?" (inventory mode) vs "I want to make..." (recipe mode)
- Recipe mode shows prominent text input for recipe request, hides ingredient multi-select
- API accepts mode + recipeRequest params
- Two completely different prompts in generateMealSuggestions:
  - Inventory mode: unchanged "Generate meals based on inventory"
  - Recipe mode: "The user wants to make: [request]. Help them make this."
- Recipe-first prompt puts user request FIRST, inventory SECOND (key insight from failed first attempt)
- Removed fragile hasSpecificRecipeRequest keyword detection code

**Files changed:**
- src/app/(dashboard)/dashboard/inspire/page.tsx - mode toggle, recipeRequest state, conditional UI, button styling
- src/app/api/suggestions/route.ts - added mode + recipeRequest to request body, pass to generateMealSuggestions
- src/lib/gemini/vision.ts - added mode/recipeRequest to MealSuggestionOptions, two separate prompts based on mode

**Decisions:**
- Two prompts vs single prompt with conditional sections - two prompts cleaner, no AI prompt confusion
- Recipe mode shows cooking methods filter (still useful) but hides remarks (recipe input IS the main request)
- Button changes color (purple) and shows truncated recipe name when in recipe mode
- Kept recipe count selector for recipe mode - alternatives/variations still useful

**PM CHECK:**
- No new bugs discovered
- Cleaned up unused imports (useRef, trackRecipeSearched, expandedSuggestion)
- Ready for user testing - test "bittergourd juice with lemon, ginger, turmeric" in recipe mode
