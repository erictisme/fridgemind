## 2026-01-10: Bug #1 Fixed - Recipe generation now respects special instructions (PRD id:1)
**Problem:** When user wrote detailed requests like "want to make bittergourd juice with lemon, orange, turmeric, ginger", system ignored request and generated random inventory-based recipes instead.

**Solution:** Updated generateMealSuggestions in src/lib/gemini/vision.ts:
- Added detection for specific recipe requests (keywords: make, want, juice, blend, soup, smoothie, salad, dish, recipe)
- When detected, prompt now makes user's request the PRIMARY goal with **CRITICAL** priority
- Prompt instructs AI to generate the EXACT dish requested, check inventory for matching ingredients, list what's missing
- Added new priority tier that takes precedence over inventory-based optimization

**Files changed:**
- src/lib/gemini/vision.ts (lines 499-549) - prompt building logic

**Decisions:**
- Used keyword detection vs AI classification - simpler, no extra API call, good enough for common recipe terms
- Made specific request override mustUseItems priority - user's explicit request > implicit inventory selection

**PM CHECK:**
- No new bugs discovered
- Ready for user testing - have user try "bittergourd juice" example to verify fix
- Next: Bug #2 (clean up item names) at priority 1

## 2026-01-10: Bug #2 Fixed - Removed confusing "Clean up item names" feature (PRD id:2)
**Problem:** Users confused by normalization banner in Groceries > Overview. Banner showed "stuck at 15%" progress, wasn't clear what it does (normalizes cryptic receipt item names like "G JAPANSE CAI XIN220" to "Japanese Cai Xin").

**Solution:** Removed the feature entirely.
- Feature was in groceries page (not inventory as PRD stated)
- Only useful for legacy receipt items uploaded before normalization was added during upload
- New receipt uploads already normalize items automatically
- Confusing UX for minimal benefit - just cluttered the analytics page

**Files changed:**
- src/app/(dashboard)/dashboard/groceries/page.tsx - removed normStatus state, normalizing state, handleNormalize function, normalization banner JSX
- Deleted: src/app/api/receipts/backfill-normalize/route.ts - no longer needed

**Decisions:**
- Removed vs fixed because: feature was niche (backfill-only), confusing to users, normalization now happens at upload time
- No data migration needed - old unnormalized items still display their raw names, just slightly uglier

**PM CHECK:**
- No new bugs discovered
- No user-facing functionality lost (new uploads still normalize)
- Next: Feature #3 (food waste tracking) at priority 2

## 2026-01-10: Feature #3 Complete - Food waste tracking counter (PRD id:3)
**Problem:** No visibility into how much food users saved from waste - needed for civic good positioning.

**Solution:** Added waste tracking widget to dashboard showing items saved vs wasted.
- Fixed /api/inventory/[id] DELETE to log to consumption_logs table (was missing)
- Added waste_stats query to /api/home-feed (counts consumed vs wasted from consumption_logs)
- Added dashboard widget showing "X items saved from waste" with save rate percentage

**Files changed:**
- src/app/api/inventory/[id]/route.ts (lines 83-98) - added consumption_logs insert on delete
- src/app/api/home-feed/route.ts (lines 26-29, 121-139, 272) - added WasteStats interface, query, response
- src/app/(dashboard)/dashboard/page.tsx (lines 28-31, 44, 220, 465-485) - added WasteStats interface, widget

**Decisions:**
- Tracked item count not kg/$ - simpler, no need to estimate weights/prices per item
- Widget only shows when items_saved > 0 - no empty state clutter for new users
- Included save rate % when items_wasted > 0 - gamification element
- Mapped delete reasons: eaten=consumed, bad=wasted, wrong=not tracked

**Scoped out for simplicity:**
- Community total / social proof (would need aggregate API, privacy considerations)
- kg/$ estimates (would need item weight/price lookup table)

**PM CHECK:**
- No new bugs discovered
- Ready for user testing - widget appears after marking first item as "Ate it"
- Next: Feature #4 (landing page improvements) at priority 3
